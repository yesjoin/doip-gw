# M16 验收报告 —— 会话层门禁（0x10 / 0x27 / 0x3E / S3）

## 1. 目标

M15 把刷写链路跑通了，但那时这台 ECU 有个不太体面的事实：**谁连上来都能刷**。
不用进会话、不用解锁，一条 `0x34` 就把镜像往下灌。

真实的 ECU 有两道门：

- `0x10 02`：进**编程会话**（默认会话里刷写服务根本不存在）；
- `0x27 01 / 02`：要种子、算密钥、交密钥（钥匙插上才准动）。

少任何一道，`0x31 FF00/FF01`、`0x34`、`0x36`、`0x37` 都该被拒。

这一步和前面十四步的区别在于：**它第一次让"这条服务能不能用"取决于之前发生过什么**，
而且这个状态**会因为时间而消失**（S3 5000ms）。所以它不是加一个分支，是加一台状态机。

## 2. 复现

```bash
cd ~/doip-gw
cmake --build build -j4
./build/session-selftest                # 61 项，纯内存，不需要 vcan0
bash tools/m16_e2e.sh 13475             # 三十七项，约 60 秒（含 S3 干等 5.6 秒）
bash tools/ci_local.sh gcc              # 20 步 33 项
```

依赖：`vcan0`、`build/stub-ecu`、`python3`（场景脚本是裸 socket，不需要 `doipclient`）。

## 3. 拓扑

- 网关：`--iface vcan0 --port 13475`，路由 `0003:7A0:7A8`
- 一台 ECU：`stub-ecu --rx 7A0 --tx 7A8 --flash --secure --seconds 22`
  - TA `0x0003`，VIN `LSVZZ0000B7654321`，`--flash-block 34`
- 传输：TCP 13475 → 网关 → `7A0/7A8` → ISO-TP（经典帧 8 字节）
- tester：主线 SA `0x0E00`；`0x3E 80` 那条**单开一条连接**（SA `0x0E01`）
- 第二条腿（端口 13476）：同一台 ECU **去掉 `--secure`**，验证 M15 的 39 项不受影响

## 5. 四个关键口径

1. **`0x7F` 和 `0x33` 是两件事**。默认会话回 `0x7F`（`serviceNotSupportedInActiveSession`），
   编程会话没解锁回 `0x33`（`securityAccessDenied`）。混成一个码，现场就分不清"客户端忘了切会话"
   还是"客户端密钥算错了"。
2. **`key = (seed + 0x12345678) ^ 0xA5A5A5A5`，32 位溢出自然截断**。故意做成能手算：
   `seed=0xFD0C8742` → `0xAAE5781F`。脚本和 ECU 是各自独立算的，对得上才算数。
3. **换会话把解锁清掉**。`0x10` 不是"换个名字"，它连安全状态一起改。所以顺序永远是
   "进编程会话 → 解锁 → 干活"，不是"解锁一次、之后随便切"。
4. **S3 超时连锁一起解、连计数一起清**。否则"放着不管"就成了绕过门禁的办法 ——
   等 5 秒再进会话，锁还在，等于锁永远解不开。

## 6. 为什么 `0x50` 要带 `P2` / `P2*`

`50 02 00 32 01 F4`：`00` 是保留位，`0x0032` = 50ms（收到请求到开始回的最长时间），
`0x01F4` 乘以单位 10ms = **5000ms**，正好是 S3。

这两个数不是装饰：诊断仪按它们决定"等多久算超时"。ECU 报小了就是自相矛盾 ——
它说自己 50ms 内回，实际擦除要 200ms，客户端早就放弃了。
所以 `SessionGuard` 里 `kP2Ms = 50`、`kP2StarMs = 5000` 与 S3 出自同一组常量（本项目两处手抄，
见边界）。

## 7. 为什么错密钥的第三次是 `0x36` 而不是又一次 `0x35`

```
第 1 次错 → 35   （还能再试）
第 2 次错 → 35   （还能再试）
第 3 次错 → 36   （锁 10000ms）
锁定期内 27 01 → 37（requiredDelayNotExpired，reason 里带剩余毫秒）
```

`0x36` 是"你已经试太多次"，`0x37` 是"时间还没到"。两个码分工明确：
拿到 `0x36` 说明刚被锁，拿到 `0x37` 说明还在锁里。脚本第 25-28 项就是这条时间线，
日志里能看到 `剩 9893 ms` —— 说明锁是按"最后一次失败"起算的。

**锁到期必须清零 `attempts_`**（`clearExpiredLock()`）。不清的话，锁一过就是"第 4 次错"，
立刻又锁上，现场看起来像"锁永远解不开"。这条在自测里是硬断言（必须等于 0）。

## 8. `0x3E 80` 与网关的"一问一答"

`0x3E 80` 的语义是"我还在，但**别回包**"（suppressPosRsp）。问题出在中间那台网关：

- 网关是**一问一答**的中继：一条请求出去，等一条应答回来，这条连接才算空闲；
- `0x3E 80` 不回包 → 网关认为"还有一条在途" → 下一条请求当场 `0x8003 0x08`（忙）；
- 再下一条就把连接搞破了。

真实网关靠 `P2` 计时器到期释放；本项目没有那条计时器（见边界）。所以脚本把这一项
**单开一条连接**（SA `0x0E01`）放到 leg 末尾验 —— 换个 SA 是因为 M13 的地址仲裁会
把同 SA 的第二条连接回 `0x8003 0x03`。

顺带一个更隐蔽的坑：**S3 干等 5.6 秒期间不回心跳，会先被网关断链**（网关心跳 3 秒）。
那时候测到的不是"S3 回落"，而是"网关把我踢了"。修法是在 `idle()` 里继续读 socket 并回 `0x0008`。

## 9. 为什么把 NRC 表抽成 `UdsNrc.h`

M15 的 `FlashTarget.h` 里有一份码常量，M16 的 `SessionGuard.h` 又要用同一批。两个头同时
被 `stub-ecu.cpp` 包含，编译器直接报：

```
error: redefinition of 'constexpr const uint8_t doip::kNrcIncorrectLength'
error: redefinition of 'constexpr const uint8_t doip::kNrcRequestSequenceError'
```

码表是**协议的一部分**，不是某个模块的私有常量。收敛成一个 `include/UdsNrc.h`，
两边都 `#include` 它 —— 这是这一步唯一的结构性改动，也是最该发生的一次重构。

## 10. 单元断言：748 → 809 项（新套件 `doip-session` 61 项）

| 组 | 覆盖 |
|---|---|
| 默认会话 | `0x27` → `7F`；`denyFlash` 也是 `7F` |
| `0x10` | `50 02 00 32 01 F4` 六字节；`03` 扩展会话；子功能 `04` → `0x12` |
| 密钥公式 | `key(1) = 0xB791F3DC`；`key(0)` 与手算一致 |
| 种子 | 非 0、一次性（两次不同）、回包与内部记账一致 |
| 顺序/长度 | 没种子就交密钥 → `0x24`；3 字节密钥 → `0x13` |
| 解锁 | `67 02`；`flashAllowed()` 变 true；已解锁再要种子 → `67 01 00 00 00 00` |
| 换会话 | 解锁清掉、刷写仍拒（刷写只认 `02`） |
| 错密钥 | `35/35/36`、锁 `10000ms`、锁定期 `0x37`、到期能重新要种子且计数清零 |
| S3 | `4999` 不动 / `5001` 回落 + 清锁、只报一次（`tick` 返回 true 一次） |
| `0x3E` | `7E 00`；`80` 空回包且重置计时；`01` → `0x12` |
| 保活计数 | 两次 `3E 00` → `2`（`3E 01` 是错子功能、不计数） |

自测**不 sleep、不需要 vcan0**：时间当参数传进去（`testerPresent(..., nowMs)`、`tick(nowMs)`）。
"真的在总线上 5 秒后回落"只能靠 `m16_e2e.sh` 称 —— 这也是为什么每个里程碑都要有一条真脚本。

## 11. M16 之后仍然没有的

- 种子是**确定性混淆**（计数器 + 乘法 + xor-shift），不是密码学随机：目的是"每次不同、可复现"。
- 密钥公式是公开的明文算法：它防"手滑"，不防"有意"。
- `0x27` 只做一档（`01/02`），没有多安全等级（真实现有 `03/04` 等更高档）。
- 锁定期固定 `10000ms`，不随失败次数递增，也不落盘（重启归零）。
- 会话状态每台 ECU 各一份，网关不知道谁解锁了谁，**网关侧无法统一审批刷写**。
- `P2*` 与 S3 的 5000ms 是两处手抄，没有从同一常量派生。
- 网关没有 `P2` 计时器，所以 suppress 请求会占住连接（见第 8 节）。
