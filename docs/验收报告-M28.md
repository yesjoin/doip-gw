# M28 验收报告 —— 把"谁"送到 CAN 侧（29 位 ID 里本来就有一格）

## 1. 目标

M27 把门关上了，但 ECU 的流水第七格还空着。当时摆在桌上两条路，两条都不该走：

- **网关自己记一份审计账**：等于让被查的人自己写笔录。网关一挂、日志一清，账就没了；而且跟 ECU 那边的流水永远对不上。
- **用 `0x2E` 把操作者标签写进 ECU**：为了记一个名字，去动被诊断的对象——要先编程会话、解锁、改 ECU 的状态。这是最不该做的事。

真正的答案在总线上：**29 位寻址的 ID 本来就有"源地址"这一格**。

```text
29 位 CAN ID = 0x18DA <目标> <源>
                  └──┬──┘  └─┬─┘
                   发给谁   谁发的   ← 这一格一直存在，只是我们以前把它冲掉了
```

所以这一步只做一件事：**网关发请求时，把 ID 的最低字节写成这台诊断仪的"位子"**，ECU 从收到的首帧里读出来，记进流水。

## 3. 机制：位子是资源，不是身份

```text
SA 0x0E00 ─┐
SA 0x0E01 ─┼─► SlotTable.take(sa) ─► 1..8 ─► CAN 源地址 0xF1..0xF8
SA 0x0E02 ─┘                                   0 = 满了 / 不知道
```

`include/SourceSlot.h` 里只有四个动作：`take` / `release` / `slotOf` / `saOf`，外加两个纯函数 `stampSource` 与 `sourceOf`。判据：

| 场景 | 结果 |
|---|---|
| 同一 SA 再来一次 | 同一个位子（重连不换名字） |
| 第 9 台 | `0`，并且**不进**（退回 `0x01`，地址账一起退） |
| 断开 | 归还（`dropConn` 里先还位子再 `routing.reset()`） |
| 11 位 ID（`0x7A0`） | 原样返回，`sourceOf` 给 `0` |

`0xF1..0xF8` 不是随便挑的：这一段的低 4 位正好可以当"位子编号"，同时避开 `0xF1`（网关自己）和 `0x00/0x01` 这些有专用含义的地址。

## 4. 三个不能含糊的顺序

1. **先还位子，再 `reset()`**。`c.slotSa` 单独存一份，因为 `routing.reset()` 会把激活的 SA 清掉；中途换过地址的连接（`0x02` 那种）也不该拿新地址去还旧位子。
2. **位子发不出来就不许进**。`take()` 给 0 时：`registry_.release()` → `routing.reset()` → 回 `0x01`。半进半不进比拒掉更难查。
3. **槽号跟着请求走，不跟通道走**。`DiagnosticMessage.actorSlot` 一路带到 worker；两台诊断仪交叠时通道是同一条、位子是两条，串号会记错人。

## 5. 落盘：v4，36 → 38 字符

```text
DOIPKEYRING 4
VER 0002
BOOT 0001
K 0001 00 <64 hex>
L 0002 70D3 02 01 0003 0002 00000007F2     ← 前 36 个字符与 v3 一模一样
SUM <16 hex>
```

"谁"**贴着秒数写**（不留空格）：这样 v3 的 36 字符前缀一个字不动，读旧文件时按长度切就行。

| 文件版本 | `L` 行 | 读进来 |
|---|---|---|
| v1 / v2 | 没有 `L` | 流水空 |
| v3 | 36 字符 | 谁 = `00` |
| v4 | 38 字符 | 谁 = 真值 |
| v4 里混了 36 字符行 | — | **判坏**（要么是搬账，要么手改过） |

## 6. 十七项验收（两段，两个进程）

```bash
bash tools/m28_e2e.sh 13500 13501
```

| 段 | 起什么 | 验什么 |
|---|---|---|
| 一 | 网关 `--stamp-sa`，三台 ECU：`0x0003`（11 位）/ `0x0006`（29 位，`--rx-mask 1FFFFF00`）/ `0x0007`（11 位） | 横幅说"改写开"；日志"位子 1（CAN 源地址 0xF1）/ 位子 2（0xF2）"是十六进制；29 位那台账上 `F2` / `F1` 两台分得开；11 位那台只记 `00`；盘上 `DOIPKEYRING 4`、L 行 38 字符；ECU 退账带"谁 F2"；收尾"位子还占着 0 个" |
| 二 | 同一批 ECU，网关**不开** `--stamp-sa` | 两台诊断仪在 ECU 账上**都是 F1**——分不开 |

段二是**对照腿**：它证明段一的绿不是因为"刚好只有一台在动"。把"没有这个能力时是什么样"也钉进仓库，是这个项目一直的做法。

## 9. 踩到的坑

1. **`L` 行多加了一个空格 → 39 字符**。格式串写成 `%08X %02X`，跟"36 → 38"的承诺当场打架，B1 立刻红。改成 `%08X%02X`。**定长格式的承诺必须用算术验一遍。**
2. **ECU 等流控仍按精确 ID 比**。改写源地址后，流控帧是从 `18DA00F2` 来的，`sendUds` 还在等 `18DA00F1`，多帧响应一条也发不出去。现象是"等 tester 流控超时"，真因是"等了但不是给我的"。修法：`sendUds` 也按 `rxMask` 认帧。**超时最会骗人——看起来是对方不回，其实是自己在筛。**
3. **日志里的 `0xF1` 打成十进制**。`std::to_string(uint8_t)` 走整型流，`0xF1` 变 `0x241`，前面还手写了 `0x`。给人看的日志，格式要自己拼。
4. **验收脚本查得太早**。横幅是启动时打的，"位子 1"是连上才发的；脚本在激活之前就 `grep`。**验收脚本的时序也是被测的一部分**——和 M27 的"ACK 当答案"同族：不是实现错，是观察错。
5. **`entryOf` 加参数忘了用**。给测试辅助函数加了 `actor` 形参却没写进结构体，`-Werror=unused-parameter` 直接顶回来——编译器替我抓了一次"以为改了其实没改"。

## 10. 与 M26 / M27 的关系

- **M26 的详情报文从 19 字节变 20**。`m26_check.py` 改成"19 或 20 都收"，并在 `m26_e2e.sh` 里把版本断言从 v3 放宽到 v3/v4：**老里程碑的验收脚本不该因为后来加字段就变红，但也不该假装 20 字节是 19。**
- **M27 的票与位子是两件事**：票回答"你是不是你自称的那台"，位子回答"动这台 ECU 的是第几号人"。有了位子，"有票的诊断仪"才在 ECU 那边留下可查的痕迹。

## 11. 边界

- 位子**会回收**，不是人。要追到人，得拿网关日志的映射表与 ECU 流水按时间对账（没做工具）。
- 只改**请求方向**；应答仍是 ECU 配的固定 ID。
- 开 `--stamp-sa` **破坏透明桥接**，所以默认关。
- 位子只有 **8 个**，第 9 台退回 `0x01`。
- **11 位寻址永远记不下人**——硬件事实。
- "谁"这两字符**不签名**，挡不住整行替换 + 重算 `SUM`。
