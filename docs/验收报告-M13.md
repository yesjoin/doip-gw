# M13 验收报告：实体级 tester 地址仲裁（0x01 / 0x03 第一次真的用起来）

M12 让答案"收一条转一条"。M13 换了个方向：不再问"答案怎么送"，而是问"**谁有资格说话**"。

先说清一件事，因为它决定了这一节做什么：**tester 的逻辑地址不是网关发的。**
ISO 13400-2 把 0x0E00–0x0FFF 整段留给外部测试设备（0x0E00–0x0E7F 法规诊断仪、
0x0E80–0x0EFF 厂商/售后增强诊断仪），地址由 tester 自己选、自己带过来。
实体要做的是**查重**与**限流**，对应 0x0006 的两个码：

| 码 | 含义 |
|---|---|
| `0x03` | 该源地址已在**另一条** TCP_DATA socket 上注册并激活 |
| `0x01` | 本实体能同时承载的 socket 都已被注册并激活（激活名额满，但 TCP 连得上） |

- 复现：`bash tools/m13_e2e.sh 13471`（一台网关 + 一台经典 ECU，多连接由裸 socket 脚本精确控制，约 25 秒）
- 结果：**通过 15 项，失败 0 项**；单元断言 **636 条**（10 套件，新增 `doip-registry` **43 项**）；
  `ci_local.sh` **17 步 30 项**全绿（含 `-O2 + -Werror`）

## 拓扑

| 角色 | 地址 / 连接 | 说明 |
|---|---|---|
| 网关 | `0x0001`，8 条 TCP / 4 个激活名额 | 两个容量分开配（M13 的关键改动） |
| ECU_A | `TA=0x0003` → `7A0`/`7A8`，经典 8 | VIN `LSVZZ0000B7654321`，`HW02` |
| A–G 七条 tester 连接 | 0x0E00–0x0E09 | 由 `tools/m13_check.py` 逐条控制"第几次发请求" |

为什么用裸 socket 而不是 `doipclient`：这一节要验的是"**同一条连接**换地址被拒、
**另一条连接**抢同一地址被拒、名额满了被拒、释放之后又能要回来"——每一步都必须精确控制
"谁在哪条 socket 上、第几次发"。第三方库一构造就自动激活一次，插不进手。

## 场景（15 项断言的主干）

| # | 动作 | 期望 | 实测 |
|---|---|---|---|
| 1 | A 用 0x0E00 激活 | `0x10` | `CODE_A=10` |
| 2 | A 用同一地址**再来一次** | `0x10`（幂等） | `CODE_A_REPEAT=10` |
| 3 | A 改 0x0E09 | `0x02` | `CODE_A_CHANGE=02` |
| 4 | B 用 0x0E00（A 还占着） | `0x03` | `CODE_B=03` |
| 5 | C/D/E 各用自己的地址 | 三条 `0x10`（凑满 4 台） | `CODE_C/D/E=10` |
| 6 | F 第 5 台（0x0E04） | `0x01`（TCP 连得上） | `CODE_F=01` |
| 7 | A 断开，B 重试 0x0E00 | `0x10`（地址还回来了） | `CODE_B_RETRY=10` |
| 8 | G 再试 | `0x01`（仍满） | `CODE_G=01` |
| 9 | B 发 `22 F1 90` | ACK + `62 F1 90` + VIN | `DIAG_VIN=LSVZZ0000B7654321` |
| 10 | 网关启动 | `最多同时激活 4 台（连接上限 8）` | ✅ |
| 11 | 网关账 | `地址冲突 1 次` / `激活名额已满 2 次` / `成功激活 6 次` | ✅ |

第 11 步的三个数可以手算：冲突只有 B 那一次；名额拒绝 F、G 各一次；
成功激活 = A、A 重复、C、D、E、B 重试 = 6。**账能对上，说明每个分支都只走了一次，没有谁被算了两次。**

## 为什么必须是"实体级"的账

M2 的 `RoutingActivation` 是每条连接一份，它管：

1. SA 合法（0x0000 是保留值、等于实体自己是方向搞反）；
2. 激活类型支持（只放行 0x00 / 0x01）；
3. **这条 socket 内不许换人**。

这三条都对，但都只在一个 socket 内部成立。第四条它管不了：
两台 tester 各开一条连接、用同一个 SA 各激活一次——每条连接看自己都是"合规"的。

网关这边一切正常，总线那头却是两个同址的诊断仪在说话：ECU 分不清，只有网关靠 `jobId` 才没把答案送错人。
所以 M13 加一张实体级的账（`include/TesterRegistry.h`）：

```
byConn_ : 连接号 → 逻辑地址
bySa_   : 逻辑地址 → 连接号
```

四种结论的**判定顺序**决定了现场看到哪个码：

| 情形 | 结论 | 理由 |
|---|---|---|
| 本连接已登记同一地址 | `0x10` 幂等 | 断线重连后重发请求是常态 |
| 本连接已登记别的地址 | `0x02` | 一个 socket 是一段已认证的上下文 |
| 地址被别的连接占着 | `0x03` | 先报"你"的问题，它更具体 |
| 名额已满 | `0x01` | 再报"我"的问题 |

身份用**连接号**而不是 fd：fd 会被内核复用，断开再开可能还是同一个数字，
拿它当身份会出现"新连接继承老连接地址"的幽灵 bug。

## 三个坑（都已经在验收里钉住）

1. **0x01 在此之前永远发不出去。** M13 之前 `maxConnections`（4）同时兼任"能激活几台"，
   第 5 个客户端连 TCP 都连不上，根本走不到路由激活。拆成 `maxConnections=8` / `maxActivated=4`
   之后，第 5 台才"来得了、排不上"——这才是 0x01 的意义。
2. **释放漏了就是地址泄漏。** `dropConn()` 里必须和 `routing.reset()` 并排一句 `registry_.release(c.id)`。
   漏了不报错、不崩，只表现为"这个地址永远在别人名下"：下一位 tester 一直吃 0x03，而你找不到那个"别人"。
3. **验收脚本自己也要被验收。** 第一版取"成功激活次数"用的是 `grep -o "激活 [0-9]*" | head -1`，
   结果抓到的是启动行 `最多同时激活 4 台` → 断言"4 次"红。改成从汇总行 `接入 N，激活 M，…` 里取 M 才对。
   这和 M12 第 5 步的教训是同一条：**断言红了先证明现象，再改数字。**

## 单元断言：593 → 636 项（新套件 `doip-registry` 43 项）

| 组 | 覆盖 |
|---|---|
| 空 / 正常 | 0 个激活；登记后 `addressOf` / `ownerOf` 双向可查 |
| 幂等 | 同连接同地址重发 → 0x10，`active()` 不涨 |
| 换址 | 同连接换地址 → 0x02；原绑定不变；被拒的地址没被偷偷登记 |
| 冲突 | 另一连接抢同一地址 → 0x03；原主人不变；`conflicts()=1` |
| 容量 | 上限 2 时第三个 → 0x01；**`conflicts()` 仍为 0**（两种错因分开记） |
| 释放 | 释放后地址可被新连接拿走；重复释放返回 false；两张表都清 |
| 观测 | 计数只涨不回退，`clear()` 才归零 |
| 边界 | 0x0EFF、64 位连接号、运行期 `setMaxActive()` |

`ctest -R doip-registry` 一秒内跑完，不需要 `vcan0`；它证明"账不会算错"，
"码真的发到了线上"只能靠 `m13_e2e.sh` 在真 socket 上称。

## 边界（写清楚，不糊过去）

- **不做地址分配**：tester 地址由 tester 自选，实体发号是厂商扩展，本项目不做。
- 判重是实体级的，但**不分接口**：标准允许同一 SA 在不同 IP 接口上分别激活，本项目只有一条 TCP。
- 名额满**不排队**：拿 0x01 的 tester 只能自己重试，网关不替它占位、也不通知"有空位了"。
- 释放只在 `dropConn` 一处；进程被杀不会留下"残留地址"（没有持久化）。
- 8 / 4 是写死的默认值，只有 `TcpServerConfig` 能改，命令行没暴露 `--max-testers`。
- 仲裁只看 SA，不看身份：没有证书、没有绑定 IP/MAC，地址仍然是自报的——
  这一层能防"误配/两台同型号诊断仪撞号"，防不了恶意冒充。
