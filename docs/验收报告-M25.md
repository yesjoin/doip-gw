# M25 验收报告 —— 清单指纹与世代（"计数一样"不等于"表一样"）

## 1. 目标

M24 的摘要是四个计数（总 / 启用 / 退役 / 吊销）。它便宜、能广播，但它只回答**数量**，回答不了**内容**：

```text
A 车装了 5 号   → 总 4 / 启用 4
B 车装了 6 号   → 总 4 / 启用 4     ← 摘要一模一样，认的不是同一把钥匙
```

车队轮换时脚本按"逐台下发"跑，一台失败重试、一台先装了别的，计数照样对得上、摘要照样全绿。**计数是数量，不是内容。**

M25 再压一层，两个数各管一件事：

| 数 | 它是什么 | 管什么 | 管不了什么 |
|---|---|---|---|
| 指纹 `u16` | SHA-256(规范串) 前 2 字节 | 内容：有哪些 id、各是什么状态 | 材料；历史上被改过几次 |
| 世代 `u16` | 每成功改一次表 +1 | 历史：这台车被动过几次 | 当前内容长什么样 |

于是三个问题都能回答：两台一样吗（指纹相同）、两台不一样吗（指纹不同并点名）、同一台被人动过吗（世代更高，哪怕指纹回原值）。

## 3. 报文

```text
22 F1B2  →  62 F1 B2 <世代 2><指纹 2>        // 6 字节，7 字节以内，可广播
```

比 M24 的摘要（7 字节）还短一个字节，所以它天然能走功能寻址 —— 这是先定信封、再定接口的又一次复用。

## 4. 规范串：不排序就没法对账

表按**装入顺序**存，两台车装钥匙的先后可能不同。不排序，同一张表在两个进程里会算出两个指纹：

```cpp
inline std::string canonicalOf (const KeyRing &ring)   // 按 id 升序："0001=00;0002=00;"
{
    std::vector<std::pair<std::uint16_t, std::uint8_t>> rows;
    for (std::size_t i = 0; i < ring.size (); ++i)
        rows.emplace_back (ring.at (i).id, stateCode (ring.at (i).state));
    std::sort (rows.begin (), rows.end ());
    ...
}
inline std::uint16_t fingerprintOf (const KeyRing &ring)   // SHA-256(规范串) 的前 2 字节
```

为什么不用"各 id 异或"：**两把钥匙互换状态时，异或正好抵消** —— 而"谁退役了、谁启用了"恰恰是最该被抓到的改动。

## 5. 世代：0 留给旧文件

```cpp
using Generation = std::uint16_t;                 // 1..0xFFFF
Generation nextGeneration (Generation g);          // 到头绕回 1，不绕回 0
```

`0` 专门留给 M23 的 v1 文件（没有 VER 行）。这样"旧文件读进来"与"从没改过"是同一件事，都不会被误当成一次真实变更。

## 6. 落盘 v2：写新读旧

```text
DOIPKEYRING 2
VER 0007
K 0001 00 <64 hex>
K 0002 02 <64 hex>
SUM 3f7c1a0e5b2d9c48
```

| 读到的头 | 处理 |
|---|---|
| `DOIPKEYRING 2` | 第二行必须 `VER <4hex>`；缺行 / 非 hex / 超 16 位 → Corrupt（**不悄悄当 0**） |
| `DOIPKEYRING 1` | 没有 VER，世代 0，表与校验照旧 |
| 其它 | Corrupt |

盘上只会写成 2，老文件不需要人手迁移 —— 要人手迁移的那一刻，现场通常已经断电了。

落盘失败的回滚也扩到世代：

```cpp
const keys::KeyRing    before    = ring;
const keys::Generation genBefore = generation;
ring.install (id, key);
generation = keys::nextGeneration (generation);
if (!persistRing (ring, generation, storePath, pwhy)) {
    ring = before; generation = genBefore;   // 盘上没这次变更，计数不能先走
}
```

## 7. 二十四项验收（三段，六个进程）

| 段 | 起什么 | 验什么 | 实测 |
|---|---|---|---|
| 一 | 三台全新表（各自一张盘上的表） | 出厂摘要 / 世代 / 指纹 | `2/2/0/0`；世代 0；三台指纹一致 |
| 一 | 同上 | 三台装 3 号 | `7101020600` ×3；世代 1；三台指纹仍一致 |
| 一 | 同上 | **假一致**：A 装 5、B 装 6、C 装 5 | 摘要 `4/4/0/0` ×3（说一致）；指纹 A=C≠B；点名 `0x0006` |
| 二 | 同一批文件重启 | 世代活过来 | 三台世代 2；逐台指纹与重启前一致 |
| 二 | 同上 | A 退役 3 号 | 世代 3；指纹变（`1459` vs `70D3`） |
| 二 | 同上 | A 改回启用 | 指纹回 `70D3`；世代 4；另两台仍 2 |
| 三 | A 的文件改写成 v1 | 写新读旧 | 世代 0；指纹 `70D3` 不变；表 `4/4/0/0` |

段一把"摘要说一致、指纹说不是"摆在一起，就是这一步存在的理由；段二的"指纹回原样、世代更高"是另一半：**内容一样不等于没被碰过**。

## 9. 踩到的坑

1. **`encode()` 加默认参数**：`encode(ring, generation = 0)` 让老调用一行不用改，但**写出来的头变成 2**，`A1/A2` 断言必须跟着改。测试断言的是"写出来的形状"，形状变了就该改断言 —— 和"文案也是接口"是同一件事。
2. **v1 兼容不能靠"版本号跳过"**：把 v1 当坏文件最省事，但那等于让所有老车升级后钥匙表全空。读旧写新是这一层的义务。
3. 这一步 e2e 一次通过，没再撞 M24 的"一条 recv 多条消息"——因为 `Tester` 已经带了报文缓冲（M24 修的坑在这里复用了）。

## 10. 边界

- **指纹 2 字节**：能在几台车里抓错，抓不住刻意构造的碰撞；抗攻击靠 `FF02` 清单签名。
- **指纹不含材料**：换材料必须换 keyId（M22 的规矩），所以"同 id 不同材料"在表里不存在。
- **世代不是全局序号**：每台各记各的，`A 版本 4` 与 `B 版本 4` 只表示"都改过四次"。
- **没有"谁改的"**：只有次数，没有操作者 / 时间戳；审计到人还得再加一层变更日志。
