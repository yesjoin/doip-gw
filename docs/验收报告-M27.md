# M27 验收报告 —— 路由激活的"入场券"（先关门，再记名）

## 1. 目标

M26 的流水记了六件事，"谁"这一格空着。原因不在流水，在门口：

```text
网关（M26 为止）："你自称 0x0E00？进来吧。"      ← 这不是身份，是自我介绍
```

M27 只做一件事：**让诊断仪证明自己是它自称的那个人**。证明不了，`0x04` 挡回去。

顺序上必须强调：**先关门，再记名**。先给陌生人发工牌、回头再补门禁，是最常见的顺序错误。把名字送进 ECU 的流水是下一步。

## 3. 报文：门就开在标准留的那 4 个字节上

```text
0x0005 = SA(2) + 激活类型(1) + reserved(4) + OEM(4)         // 11 字节
                                      └── 标准留给厂商 ──┘
```

载荷末 4 字节装一张票：

```text
token = HMAC-SHA256(secret, "doip-ra|<SA 四位十六进制>") 的前 4 字节
```

实测（`secret = 00112233445566778899aabbccddeeff…eeff`）：

```text
SA=0x0E00 → token C32951F0        SA=0x0E01 → token 另一个值（票绑地址）
```

应答两种：

```text
0x0006 码 0x10  成功（票对）
0x0006 码 0x04  缺认证（没票 / 票不对 / 7 字节变体没处放票）
```

`0x04 MissingAuthentication` 是 ISO 13400-2 响应码表里现成的一格，以前注释写着"本项目不做"，这一步做上了。

## 4. 为什么是 HMAC

`sha256(secret || 消息)` 有**长度扩展**：拿到 `H(secret||m)` 的人可以在 `m` 后接自造的尾巴，不掌握 secret 也能算出"合法"的 `H(secret||m||尾巴)`。HMAC 用内外两层盐（`0x36` / `0x5c`）堵死这条路：

```text
HMAC(K,m) = SHA256( (K^0x5c) || SHA256( (K^0x36) || m ) )
```

自测 A 组用 **RFC 4231 的 6 条官方向量**钉尺子（含 131 字节超块长 key，专门验"长 key 先压成 32"的分支）。

## 5. 为什么票要绑 SA

同一把 secret，`0x0E00` 和 `0x0E01` 的票不是同一个值。于是"0E00 的票"不能原样当"0E01 的票"用。验收里有一条专测这个：拿 `0x0E01` 的票激活 `0x0E00`，必须 `0x04`。

## 6. 门在哪一步关：三段顺序

```text
① 连接级（M2）   这条 socket 里 SA 不许换人
② 凭据（M27）    票不对 → 0x04，并且 reset()
③ 实体级（M13）  同址冲突 0x03 / 名额满 0x01
```

为什么凭据在地址仲裁**之前**：`0x03` 的意思是"两台都到场了"，票不对的意思是"这一台根本不该到场"。后者更根本，先挡。

为什么必须 `reset()`：`handle()` 已经把这条 socket 置成激活态了，只回一个 `0x04` 而不撤销，就是"拒了但门还开着"。M13 踩过同一个坑。验收里"被挡的连接发诊断请求 → 负应答而不是 UDS 回答"就是钉这件事的。

必然结果：**7 字节的 `0x0005` 老变体没有 OEM 字段 → 开票后必被挡**。这不是 bug。

## 7. 固定时间比较

```cpp
const std::uint32_t diff = want ^ got;
std::uint8_t acc = 0;
for (int i = 0; i < 4; ++i) acc |= (diff >> (i * 8)) & 0xFF;
return acc == 0;
```

`want == got` 一发现不同就 return，"差在第几个字节"会从耗时里漏出来。4 字节的票已经短，再送一个逐字节试探的侧信道，等于把门虚掩着。

## 8. 十项验收（两段，两个进程）

```bash
bash tools/m27_e2e.sh 13498 13499
```

| 段 | 起什么 | 验什么 |
|---|---|---|
| 一 | 网关**不开票**（回归腿） | 11 字节零 OEM 激活 `0x10`；7 字节老变体也 `0x10`；读 VIN 通；横幅明说"凭据关"；退账里没有凭据账 |
| 二 | 网关**开票**（新能力腿） | 对票 `0x10` 且能正常诊断；没票 `0x04` 且那条连接发诊断只得负应答；借 `0x0E01` 的票 `0x04`；7 字节变体 `0x04`；`0x0E01` 带自己的票 `0x10`；日志里的票 = python 独立算出的票；退账"通过 2 次 / 挡回 3 次" |

段二那条对账（网关日志 vs Python `hmac`）是这一步最重要的一条：**两条独立实现算同一个值**，撞上了才说明协议立住了；一条代码自己跟自己比，永远绿。

## 9. 断言

```text
doip-activationauth（新）26 项
  A 官方向量       8 项   RFC 4231 TC1/2/3/4/6/7 + 确定性 + 改 key 就变
  B 为什么是 HMAC  5 项   ≠ sha256(secret||msg) / 换 SA 变 / 换 secret 变
  C 校验           6 项   对的过 / 全 0 不过 / 差 1 bit 不过 / 借票不过 / 文本 8 位
  D 解析密钥       7 项   63/65 位不认 / 非 hex 不认 / 大写也收 / 全 0 语法合法
```

## 10. 踩到的坑

1. **`out.reason` 被 M13 的登记分支整句覆盖**：凭据通过时往 `out.reason` 后接"凭据已验证"，紧接着登记成功分支 `out.reason = "…激活成功…"` 把它吃掉，日志里只剩"激活成功"，验收两条 grep 红。改成先存 `authNote`、所有仲裁做完再拼。**M26 的"流水：…"也是死在同一处**。
2. **python 把 `0x8002` 正应答当答案**：网关先 ACK 再转发。只读一条会读到 `00 03 0E 00 00`（看着像个奇怪的 UDS），修法是跳过 `0x8002` 继续等。
3. **UDS 答案前面还有 4 字节地址**：`0x8001` 载荷是 `SA+TA+UDS`，直接 `startswith("62F190")` 永远红，要先切掉 8 个 hex。
4. **测试数据少写一位（63 字符）**：解析失败 → 变量未赋值 → 两把"不同"的 secret 算出同一个 token，"不同才对"的断言反而红。**坏测试数据会让正确的实现看起来是错的。**

## 11. 边界（这一步之后仍然没有的）

- **4 字节 = 32 位**：对着一条连接硬猜，期望 2^31 次。挡得住随手试，挡不住有耐心的攻击者。标准只留 4 字节，这本身就是"身份不该做在这一层"的证据。
- **静态票可重放**：抓到一次 `0x0005` 就能原样再发。协议里没有 nonce 的位置，真车靠 TLS / 证书（`0x0005` 的 `0xE0 CentralSecurity` 类型）。
- **预共享密钥**：网关与每台诊断仪共有同一把 secret，谁泄露谁全泄露。
- **名字还没进 ECU 的流水**：ECU 仍然只知道"从哪条通道进来的"。这一步只关门，**记名是下一步**。
