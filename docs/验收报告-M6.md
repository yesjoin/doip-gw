# M6 验收报告：多 ECU 路由表

验收目标不是"能通"，而是**证明每一条诊断都落到了它该落的那条通道上**。

- 复现：`bash tools/m6_e2e.sh 13461`（自起两台 ECU + 网关，约 40 秒）
- 结果：**通过 9 项，失败 0 项**；单元断言 396 条（6 套件）；`ci_local.sh` 10 步 23 项全绿

## 拓扑

| 角色 | 地址 | CAN 收发 | VIN / 其他 |
|---|---|---|---|
| 网关实体 | `0x0001` | — | UDP 发现声明 VIN `LSVAA0000A1234567` |
| ECU_A（项目一 `uds-demo`） | `TA=0x0002` | `7E0` / `7E8` | VIN `LSVAA0000A1234567` |
| ECU_B（`stub-ecu`） | `TA=0x0003` | `7A0` / `7A8` | VIN `LSVZZ0000B7654321`，HW `HW02` |
| 表外地址 | `TA=0x0004` | — | 期望 `0x8003 0x03` |

## 六条证据

| # | 要证明的事 | 实测 |
|---|---|---|
| 1 | 表本身对 | 启动打印 `TA=0x0002 → 7E0/7E8 (ECU_A)`、`TA=0x0003 → 7A0/7A8 (ECU_B)` |
| 2 | TA=2 打到 A | `22 F1 90` → VIN `LSVAA0000A1234567` |
| 3 | TA=3 打到 B | 同一 DID → VIN `LSVZZ0000B7654321`（与 A 不同才算路由生效） |
| 4 | B 的服务真在跑 | `22 F1 91` → `62 F1 91 48 57 30 32`（`HW02`） |
| 5 | 表外地址明确拒 | `TA=0x0004` → `0x8003`，NACK `0x03`，`SA=0x0004 / TA=0x0E00` 反向填 |
| 6 | 并发不串包 | A 3/3 条全 `62 F1 90...`，B 3/3 条全 `62 F1 91 48 57 30 32` |

## 网关记账（同一次跑）

```
接入 6，激活 6，诊断请求 10（ACK 9 / NACK 1）
转发 9 条，失败 0 条（其中目标地址不认识 0 条），最长排队 0 ms
  TA=0x0002（7E0/7E8）：转发 4 条，失败 0 条，发帧 8，收帧 12，超时 0，序号错 0，迟到帧丢弃 0
  TA=0x0003（7A0/7A8）：转发 5 条，失败 0 条，发帧 6，收帧 7，超时 0，序号错 0，迟到帧丢弃 0
```

4 + 5 = 9 与"共发 9 条诊断"吻合；分通道记账，出问题能立刻定位是哪条。

## 本轮修掉的问题

1. **应答源地址写死**（真 bug）：`0x8002`/`0x8003` 源地址原为 `entityAddress`，M5 因实体与 ECU 地址相同而隐藏；
   M6 分开后 `doipclient` 把 ACK 当噪声 → 全超时。改为"源 = 请求 TA，目标 = 请求 SA"，四处。
2. `doip_gateway.cpp` 注释行尾 `\`（`-Wcomment`，`-Werror` 会红）。
3. `RouteTable.cpp` 的 `std::to_string(0x0002)` 打成十进制 → 改 `snprintf("0x%04X")`。
4. 测试脚本三处过期断言：`转发 6 条`→9、`B 的每条响应都是`→`都以`、`bytes(r.vin)` 在 `doipclient`
   返回 `str` 时抛 `TypeError`（改为 str/bytes 都收）。

## 已知边界

- 路由表静态：启动定型，运行期不能增删，也不从发现/诊断配置拉表。
- 一个 TA 只对应一对 ID；同一 ECU 挂两个 TA（子网关）不支持。
- 仍"一把锁串行"，未在多节点高负载总线上称时间。
- 29 位 ID 只验"存得下、传得动"，无真机对打；不支持 CAN FD / 功能寻址。
