# 验收报告 · M31：读什么也分档（0x22 的 DID 白名单）

> 项目三 `doip-gw`（DoIP 诊断网关）· 第 32 个里程碑
> 一句话：**M30 管"能不能做这个动作"，M31 管"能不能读这个东西"。**

---

## 1. 这一步要解决的问题

M30 把请求分成三档，但只看服务号：`0x22` 一律"读档就够"。于是任何一台读档诊断仪都能读走：

- `0xF184` 指纹 —— 能判断车上装的哪个包、有没有被换过；
- `0xF1B0` 钥匙表 —— 等于把"这台车认哪些钥匙"整份交出去；
- `0xF1B2` 清单指纹、`0xF1B3` 流水概览 —— 历史与版本信息。

同一档"读"，读的东西不一样重。M31 在读档之内再分一次。

## 3. 机制：抬一个数，判定不动

```cpp
enum class Level { Open, Guarded, Secret };         // 公开 / 受限 / 锁死
Tier tierOf(Level)                                  // 公开→读 受限→写 锁死→刷写
bool classify(uds, len, DidInfo&)                   // 只认 0x22 且长度 ≥3
class DidPolicy { setDefault / defaultLevel / set / levelOf / size / didAt / levelAt }
Tier needFor(table, uds, len, base, DidInfo&)       // 不是 DID 读 → 原样返回
```

`needFor` 做两件事：查出这条读的是哪个 DID、属于哪一级，然后把"要什么档"抬到 `max(base, tierOf(level))`。抬完的档仍然交给 M30 的 `PermissionTable::decide` —— **阶梯、SA 表、默认档、`7F <SID> 33` 全部复用**，这一层只改一个数。

级别的映射：

| 级别 | 需要的档 | 典型 DID |
|---|---|---|
| 公开 Open | 读 | `F190` VIN、`F191` 硬件版本、`F186` 当前会话 |
| 受限 Guarded | 写 | `F184` 指纹、`F187` 零件号、`F188` 软件指纹 |
| 锁死 Secret | 刷写 | `F1B0` 钥匙表、`F1B1` 清单摘要、`F1B2` 清单指纹、`F1B3` 流水概览 |

## 4. 四个口径

1. **只碰 `0x22`**：`0x19` 读 DTC、`0x2E` 写 DID 一个字节都不动。写 DID 的敏感度归 M19（编程会话 + 解锁）和 ECU 的 `0x27` 管。
2. **不认识的 DID 按"受限"**：DID 空间 65536 个，厂商私有的一大片；默认公开等于默许读走一切。想读什么就点名。
3. **默认级别可配，但要看得见**：`--did-default open` 能放宽，横幅必须写"默认级别：公开"。
4. **`--did-guard` 单独给时自动打开防火墙**：白名单只是把"要什么档"变高，判定与执行在防火墙那一层；少了它这张表只是纸上的话。自动行为要在横幅里自证。

## 5. 命令行与日志

```bash
./build/doip-gateway --iface vcan0 --port 13506 --seconds 18 \
    --route 0x0006:18DA00F1:18DAF100:网关ECU --power-mode 1 \
    --enforce-ops --grant 0E00:read --grant 0E01:write --grant 0E02:flash --default-grant read \
    --did-guard --did-default guarded \
    --did F190:open --did F186:open --did F184:guarded --did F1B0:secret
```

```text
DID 白名单：开（0x22 读的 DID 再分三档：公开 < 受限 < 锁死；公开→读档 / 受限→写档 / 锁死→刷写档）
  0xF190 → 公开（VIN）
  0xF184 → 受限（指纹）
  0xF1B0 → 锁死（钥匙表）
  默认级别：受限（没登记的 DID 按这一级）；不够档就替 ECU 回 7F 22 33（未转发）
```

```text
权限挡回：SA 0x0E00 想「读 DID 0xF1B0（钥匙表，锁死级）」(刷写档)，但它只有「读」（DID 抬档挡的） → 替 ECU 回 7F 22 33（未转发）
DID 白名单：因 DID 级别不够而挡回 4 条
```

最后那一行是这一层自己的账：只报"挡回 N 条"看不出是服务号不够还是 DID 太敏感。

| 段 | 起什么 | 验什么 | 项 |
|---|---|---|---|

| 二 | 只开防火墙，不开白名单 | 读档读 `F184` / `F1B0` / `F1FF` 全都不是 33；日志没有 DID 那一行账 | 7 |

段三是这套设计里最容易被悄悄放宽的地方：谁都能加 `--did-default open`，可那样"没登记的 DID"就全公开了。所以段三同时验两件事——默认确实放宽了，而显式写成锁死的 DID 没有被默认档顺手放过。

## 9. 踩到的坑

1. **断言忘了把结果填进去**：`isRead({0x22,0xF1,0xB0}) && d.did == 0xF1B0` 没传 `&d`，`d` 还是上一条留下的值，红得莫名其妙。看到"这条明明该过"，先看被测变量是不是根本没被写。
2. **`19 01` 差点被当成 DID 读**：长度够、也是"读"，但服务号是 `0x19`。测试专门留一条 `R_19` 断言"不是 33"，把"白名单只认 0x22"钉住。
3. **`--did-guard` 单独给**：想让它报错退出，会让人卡在配置上；改成自动打开防火墙 + 横幅自证。

## 10. 与 M30 的关系

```
M30：动作级   0x22/0x19/0x3E 读，0x10/0x27/0x2E… 写，0x31/0x34/0x36/0x37 刷写
M31：参数级   同样是 0x22，读 F190（公开）→ 读档够；读 F1B0（锁死）→ 要刷写档
```

两层是**同一张表**：M31 只把"这一条需要什么档"抬高一次，判定还是 M30 的判定。所以 M30 的全部性质（阶梯、默认档、SA 绑定、先 ACK 再拒、`7F <SID> 33`）原样继承。

## 11. 边界

- 只管"读哪个 DID"，不管读几条、读多快：没有配额与速率。
- `0x22` 一次带多个 DID 的写法只认第一个。
- `0x2E` 写 DID 的敏感度不归这一层。
- 表是命令行配置，能改配置就能提权（与 M30 档位、M27 票同一信任模型）。
- 只在网关这一跳生效，能直接接 CAN 的人绕过。

## 12. 结论

M31 把"读"这一档按 DID 再分三级，复用 M30 的三档阶梯与判定，越权仍然不转发、替 ECU 回 `7F 22 33`；退账多一行"因 DID 级别不够而挡回 N 条"。48 项单元 + 40 项端到端 + 35 步本地 CI 全绿。
