# M26 验收报告 —— 变更流水（谁改的 / 什么时候 / 动了哪把）

## 1. 目标

M25 把表压成两个数：指纹管**内容**、世代管**历史**。可现场要的不是两个数，是一句话：

```text
售后："这表谁动过？"
我们："动过四次。"          ← 这不是回答
```

M26 每成功改一次表就记**一条**流水，六个字段各回答一件事：

| 字段 | 回答什么 |
|---|---|
| 世代 `u16` | 属于哪一段历史（与 `F1B2` 报的世代对得上） |
| 指纹 `u16` | 改完**之后**表长什么样 |
| 动作 `u8` | 装入 01 / 退役 02 / 复活 03 / 吊销 04 / 重建 05 |
| 通道 `u8` | 上电参数 00 / 物理 01 / 广播 02 / 重建 03 |
| keyId `u16` | 动的是哪一把（重建时为 0） |
| 时间 | 第几次带变更的上电 + 那次上电后多少秒 |

## 3. 报文

```text
22 F1B3      →  62 F1 B3 <条数 1><最近动作 1><最近 keyId 2>                 // 7 字节，可广播
             →  62 F1 B3 00                                              // 没有变更时 4 字节
31 01 02 0B <i> →  71 01 02 0B <i><世代 2><指纹 2><动作 1><通道 1><keyId 2><上电 2><秒 4>   // 19 字节，只能物理寻址
```

为什么详情用例程不用 DID：`0x22` 的 DID 严格是 2 个字节，塞不下"第几条"这个参数；再开一个 `F1B4` 也不对——那是"另开一列"，不是"同一列的某一行"。

为什么"没有变更"回 `62 F1 B3 00`：**没有变更这件事本身要能说出口**，不能拿一条"动作 = 0"的假记录去顶。`Act` 从 01 起编，0 专门表示"什么都没有"。

## 4. 时间：没有 RTC，只能报相对时间

```cpp
e.boot    = 第几次带变更的上电;    // u16
e.seconds = 那次上电之后多少秒;    // u32
```

这台 ECU 没有 RTC、也没有 GNSS。它**诚实**能报的只有这两段；别的时间都是编的。在这一层编一个假时间戳，比没有时间戳更坏——它会让人相信它。要绝对时间必须有外部授时（`0x2E` 写时钟、或证书里的时间），那是另一层的事。

`boot` 只在**真有变更落盘时**才写下去（不单独为它擦一次 flash），代价是它的名字要诚实：

> 这是"带变更的上电次数"，不是"上电次数"。

**盘上的数只描述已经发生的账，内存里的数描述这一次上电**：出厂文件写 `BOOT 0000`，同一进程的第一次变更写 `BOOT 0001`；重启读到 1，内存里按 2 算，再改一笔才写 2。旧的那几笔永远保持它们当时的号——时间不跟着新账往前跑。

## 5. 谁：只有通道，没有身份

网关不认诊断仪是谁（DoIP 层没有鉴权）。能记的只有"从哪条通道进来的"：上电参数 / 物理寻址 / 广播 / 重建。

记错"谁"比不记更坏，因为它会给一个错的人定罪。所以文档里把这条边界写在明处，而不是用一个 `actor` 字段假装知道了。

## 6. 环形 8 条

定长 8，满了丢最旧的。这是"最近发生了什么"的环形记录，不是审计日志：

- 审计日志要能无限长、能导出、不可篡改——那是车队后台的事；
- 定长 = 内存可预算、落盘可预算、读一条的报文长度可预算；
- "丢最旧的"要写进说明书：**它记得住最近 8 笔，记不住全部**。

## 7. 落盘 v3：写新读旧

```text
DOIPKEYRING 3
VER 0004
BOOT 0002
K 0001 00 <64 hex>
L 0003 70D3 01 01 0003 0001 00000012
SUM 3f7c1a0e5b2d9c48
```

`L` 行定长 36 字符：`L <世代 4> <指纹 4> <动作 2> <通道 2> <keyId 4> <上电 4> <秒 8>`。落盘顺序是**旧 → 新**：读的一方只有 `append`，写的一方要是也按"新在前"，读回来就整颠倒——写顺序和读顺序必须互相抵消，这件事一次定死。

| 版本 | VER | BOOT | 流水 | 读进来 |
|---|---|---|---|---|
| v1（M23） | 无 | 无 | 无 | 世代 0、上电序 0、流水空 |
| v2（M25） | 有 | 无 | 无 | 世代照读、上电序 0、流水空 |
| v3（M26） | 有 | 有 | 有 | 全都在 |

- v3 缺 `BOOT` 行 → Corrupt（不猜 0：猜出来的时间没有意义）；
- v2 文件里出现 `L` 行 → Corrupt（"版本说没有账，文件里有账"）；
- 流水超过 8 条 → Corrupt（不截断）。

自洽检查一条：`log.at(0).generation` 必须等于 `VER`，不等判坏——这是"合法两段拼成一份新的再重算校验和"的典型样子，校验和抓不到这一类。

**但"有世代、没流水"不判坏**：那是 v2 升上来的样子（表可信、账本没写过）。判坏的代价是把一张能用的表变成空表；账本缺页不带来这个后果。两件事代价不同，处理也不该一样——这一条只报，启动横幅喊出来。

## 8. 三十一项验收（三段，六个进程）

| 段 | 起什么 | 验什么 | 实测 |
|---|---|---|---|
| 一 | 三台全新表 | 出厂概览 | `62 F1 B3 00`（条数 0，4 字节） |
| 一 | 同上 | 三台各装 3 号 | `1 条 / 装入 / 物理 / 0x0003 / 第 1 次上电`，`sec=2` |
| 一 | 同上 | **一条广播退役三台** | `7101020700` ×3；概览 `2 条 / 退役 / 0x0003`；通道 `02` |
| 一 | 同上 | 逐台复活 | 动作 `03`（复活）不是 `01`（装入）；通道 `01` |
| 一 | 同上 | 对账口径 | 流水里的指纹 = `F1B2` 现在报的指纹 |
| 二 | 同一批文件重启 | 条数与上电序 | `0003:3 / 0006:2 / 0007:2`；世代 3、指纹 `0EDF` 不变 |
| 二 | 同上 | 旧账时间 | 旧的那条仍是 `boot=1` |
| 二 | 同上 | 再改一笔（装 `0x0004`） | `gen=4, boot=2, key=0004`；上一条仍 `boot=1` |
| 三 | A 的文件降级 v2 | 表 / 世代 / 流水 | `4/4/0/0`、世代 4、流水空；横幅"改过 4 次但没有流水" |

段二那两条并排放着就是这一步的理由：**新账第 2 次、旧账第 1 次**。时间不能跟着新账一起往前跑。

  C 与表联动      6   指纹记"改完之后" / 吊销≠退役 / 通道有话说 / dump 带 keyId 与版本
  D 版本落盘     22   v3 三行头 / 流水按旧→新写 / 读回新在前 / v2 兼容 / 缺 BOOT / 世代与 VER 不符 / 9 条 / 落盘往返 / 无 log 默认参数

## 10. 踩到的坑

1. **`boot` 第一次写成了 0**：全新表（`Missing`）时把"这次上电"也当成 0，第一笔变更就记成"第 0 次上电"，读出来像"没有变更"。e2e 里 7 条红全是这一个原因。改成"盘上写 `BOOT 0000`（出厂）、内存里按 1 算下一次"。**盘上的数只描述已经发生的账**——这一条想清楚，改起来只有两行，想不清就会去改断言。
2. **`dump()` 的空文案带括号**：横幅印成"最近 0 条（（还没有变更））"。文案也是接口，少一层括号就少一次误读。
3. **降级脚本也要认新行**：段三把 v3 改成 v2、M25 段三把 v3 改成 v1，都得显式跳过 `VER` / `BOOT` / `L`，否则会把 `BOOT` 行当成 `K` 行写进去，读出来判坏。
4. **M25 的 e2e 同步改断言**：它原来 grep `DOIPKEYRING 2`。格式一升版，老里程碑的脚本也要跟着改——不是删断言，而是改成认新格式（"写新"这件事变了，断言就该变）。

## 11. 边界

- **没有身份**：只记通道，不记"谁"。要"谁"得先有 DoIP 鉴权（M27 起的事）。
- **没有绝对时间**：只有"第几次带变更的上电 + 秒"；跨车对时靠后台，不靠 ECU。
- **只记 8 笔**：第 9 笔挤掉第 1 笔；要全量得导出到后台。
- **重建会把账一起推倒**：`--reset-key-store` 是"回到出厂"，表和历史一起清。要留证据就不要重建——吊销一把（`--revoke-key`）才是正路，它留痕、也不抹别人。
