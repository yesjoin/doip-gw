# M19 验收报告 —— 刷写前置条件（0x22 读身份 / 0x2E 写指纹 / 0x31 01 0203）

## 1. 目标

M16 的门回答"你是谁、有没有钥匙"，不回答"现在合不合适"。
一台 11 伏的车、一个没切会话的 tester、一个正在下载中途的连接，都能拿到钥匙然后刷成砖。

M19 在 `0x34` 之前补一层判断，分两半：

- **读**（`0x22`）：零件号 `F187`、软件版本 `F188`、序列号 `F18C`、电压 `F1A5`、指纹 `F184`；
- **写**（`0x2E`）：只放开 `F184` 一个 DID，且和刷写共用同一道门；
- **判**（`0x31 01 0203`）：电压 ≥ 11500 mV、会话 0x02、已解锁、不在下载中，四条全过才回 `00`。

## 2. 复现

```bash
cd ~/doip-gw
cmake --build build -j4
./build/preconditions-selftest          # 24 项，纯内存，不需要 vcan0
bash tools/m19_e2e.sh 13481 13482       # 四十项，约 40 秒（两条腿）
bash tools/ci_local.sh gcc              # 23 步 36 项
```

依赖：`vcan0`、`build/stub-ecu`、`python3`。

## 3. 读的五个 DID（本项目口径）

| DID | 内容 | 长度 | 可写 |
|---|---|---|---|
| `F187` | 零件号（ASCII） | 12 | 否 |
| `F188` | 软件版本（ASCII） | 8 | 否 |
| `F18C` | 序列号（ASCII） | 10 | 否 |
| `F1A5` | 电池电压（u16 大端，**mV**） | 2 | 否 |
| `F184` | 刷写指纹（u32 大端） | 4 | **是**（`0x2E`） |

读数例子（能手算）：

- `12400 mV` → `0x3070` → `62 F1 A5 30 70`
- `11000 mV` → `0x2AF8` → `62 F1 A5 2A F8`
- `9812 mV` → `0x2654` → `26 54`（不是 `98 12`，量纲是 mV 不是 V）

## 4. `0x2E` 的四道拦（每种"不行"一个码）

| 拦在哪 | 回答 | 诊断仪该做什么 |
|---|---|---|
| 默认会话 | `7F 2E 7F` | 先 `0x10 02` |
| 编程会话但没解锁 | `7F 2E 33` | 先 `0x27` |
| 写只读 DID（如 `F187`） | `7F 2E 31` | 找错对象了 |
| 数据长度不是 4 | `7F 2E 13` | 改请求长度 |

成功回 `6E F1 84`；随后 `0x22 F1 84` 读回同一值（跨请求保存，不是回显）。

## 5. 前置条件检查：正响应 + 状态，不是 NRC

```
0x31 01 0203
  → 71 01 02 03 00   四条全过，可以刷
  → 71 01 02 03 01   有一条不过，现在别刷
```

请求本身合法（你就是在问"能不能刷"），答案是"不能"，这是合法的否定结论。
回 NRC 会让诊断仪以为服务用错了，去改请求，而它真正该做的是去充电或去切会话。

日志逐条打出来，哪条 ✗ 一眼看见：

```
前置条件：不满足 → 01（电压 11000 mV ≥ 11500 ✗；会话 0x02（编程） ✓；已解锁 ✓；不在下载中 ✓）
```

## 7. `0x22` 一个码，四种意思

| 场景 | 码 | 意思 |
|---|---|---|
| `0x34` 没先擦除（M15） | `7F 34 22` | 状态机顺序不对 |
| `0x31 FF01` 镜像为空（M15） | `7F 31 22` | 没有东西可校验 |
| `0x11` 刷写中途复位（M17） | `7F 11 22` | 现在不能动，会变砖 |
| `0x34` 电压不足（M19） | `7F 34 22` | 条件不满足，先去充电 |

一个字节装不下四种理由，所以状态码只给结论，原因进日志 —— 这是前几步一直的规矩。

## 8. 两个真实踩到的坑

1. **自测里把 `read()` 和 `hex()` 写在同一个表达式**
   `check(d.read(0xF187, r, why) && … "（" + hex(r) + "）")`：求值顺序不确定，
   日志打出的是**上一次**的 `r`（A1 打印空、A3 打印 A1 的内容、A6 打印 A5 的内容）。
   改成"先读进 `r`、再判、再拼日志"，一次就对了。日志错了比断言错了更麻烦 —— 断言至少会红。
2. **`answer()` 给 `read()` 传了 `std::string()` 临时量**
   `read` 收的是 `std::string&`，非 const 引用绑不上右值：
   `error: cannot bind non-const lvalue reference of type 'std::string&' to an rvalue`。
   加一个局部 `readWhy` 解决。

另外一处小坑：`m19_check.py` 里手误写了 C 的 `&&`，python 直接 `SyntaxError`。
所以 `m19_e2e.sh` 之前先 `python3 -m py_compile` 过一遍，比跑到一半才发现划算。

## 10. 边界

- 电压是 stub 报出来的常量，不是真测；真机要接 ADC，中途掉电靠硬件欠压保护。
- `F184` 写进去没有回滚手段，写错只能再写一次。
- `0x2E` 只放开 `F184`，真 ECU 的可写表（日期、编程计数、匹配值）每一个都要单独定门禁。
- 前置检查是一次性快照：`0x36` 期间不再判（"条件在变，判据只在门口"）。
- 身份 DID 全是常量字符串，没有"从 Flash 读出来"，也没有零件号不符就拒刷的策略判断。
