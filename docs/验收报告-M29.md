# M29 验收报告 —— 位子 → 真身份（两边各记一半，再拿工具对账）

## 1. 目标

M28 把"第几号位子"送到了 ECU，然后把界线画在那里：位子会回收，它不是人。要追到人，当时写下的办法是"把网关日志里的 `0x0E00 → 1` 映射表和 ECU 流水按时间对起来"——但没做工具。

这一步把那个工具做出来，同时把"能不能不做成让被查的人自己写笔录"这件事讲清楚：

- M28 否掉的是"**网关的账顶替** ECU 的流水"——那等于让被查的人自己写笔录，网关一挂账就没。
- 现在做的是"**补另一半**"：ECU 记"第几号位子"，网关记"哪台 SA 在什么时间段占着几号位子"。**两边各记各的，谁也不能替谁说话**，再由第三方工具把两张账拼起来。

所以产物不是更聪明的网关，是**一份能被质疑的账**（`include/SlotLedger.h`）加**一个敢说"我不知道"的工具**（`tools/doip_audit.cpp`）。

## 3. 机制：一条租约 = 谁占着哪个位子，从第几秒到第几秒

```cpp
struct Lease { slot, sa, conn, tookSec, freeSec, open };
void noteTake    (slot, sa, conn, sec);   // 在位子真的发出去之后记
bool noteRelease (slot, sa, sec);         // 断开就还；还错 → false + orphanReleases++
Verdict resolve  (slot);                  // Unique / Ambiguous / Unknown
```

三条口径：

| 原则 | 具体做法 |
|---|---|
| **不猜** | 一个位子被 ≥2 台 SA 用过 → `Ambiguous` + 候选清单，不挑一个最像的 |
| **不合并** | 同一台断线重连是两条租约；`noteTake` 只关掉同槽的旧 open 租约，不改写历史 |
| **能自证** | 落盘带 `SUM`（复用 `keys::checksumOf`）；半截 / 手改一律判坏，坏账不参与对账 |

满了（`kMaxLeases = 64`）丢最早那条并记 `dropped`——**丢了多少要能看见**，否则"账很干净"是假的。

## 4. 时间对不齐，所以不假装对得齐

```text
ECU：第 N 次上电 + 上电后第 s 秒      ← 掉电归零，没有日历
网关：本次进程单调秒（steady_clock）    ← 重启归零，没有日历
```

没有共同时基。所以判定只用"**这个位子在这次运行里被几台不同的 SA 用过**"：0 = 查不到，1 = 唯一，≥2 = 歧义。时间戳照记（给人看先来后到），**不参与判定**。

## 5. 落盘：`DOIPSLOTS 1`

```text
DOIPSLOTS 1
P 01 0E00 00000001 0000000A 00000014
P 02 0E01 00000002 0000001E --------
SUM <16 hex>
```

`P` 行定长 **36**：`P ` + `槽2` + ` ` + `SA4` + ` ` + `连接8` + ` ` + `取秒8` + ` ` + `放秒8`，**没还的写 8 个减号**。

- 连接号用 8 位而不是 4 位：M13 的连接号是自增的 64 位整数，4 位到 65535 就溢出，**一溢出定长就破**。
- 读盘要求：版本行 `DOIPSLOTS 1` / 每行 36 字符 / 槽在 1..8 / 末行 20 字符 `SUM` / 校验和对。任一不符整份判坏。

## 6. 三种结论，一个词表

```text
唯一   → 0x0E01（位子 2）
歧义   → 位子 1 在这次运行里被 2 台用过（0x0E00 / 0x0E02）
查不到 → 位子 3 不在网关账里（没开 --slot-ledger？账被截断了？）
```

`verdictName()` 让日志和审计工具用同一套词。**"查不到"和"没问题"必须是两个词**——混成一个词，查案的人就再也分不出"这账没记"和"这账记着没问题"。

## 7. 对账工具 `doip-audit`

```bash
doip-audit --key-store <ECU 的钥匙表> [--slot-ledger <网关的位子账>] [--strict]
```

```text
第 1 条（最新）：复活 0x0001，物理寻址，版本 0002，第 1 次上电 +2s，谁 F2
  → 0x0E01（位子 2）
第 2 条：退役 0x0001，物理寻址，版本 0001，第 1 次上电 +1s，谁 F1
  → 0x0E00（位子 1）
结论：可唯一还原 2 条，歧义 0 条，查不到 0 条，不知道（00）0 条（共 2 条）
```

| 退出码 | 含义 |
|---|---|
| 0 | 没有歧义（含"谁 = 00"这种正常情况） |
| 1 | 文件打不开 / 格式坏 |
| **2** | `--strict` 且存在歧义或查不到 → CI 判红 |

`谁 = 00` 单独计数：11 位寻址 / 上电参数 / 没开 `--stamp-sa`，都是正常结果，不算错。

## 8. 三十一项验收（三段）

```bash
bash tools/m29_e2e.sh 13502 13503
```

| 段 | 起什么 | 验什么 |
|---|---|---|
| 一 不撞位子 | 网关 `--stamp-sa --slot-ledger`，`0x0006`（29 位）+ `0x0007`；A 激活后**不退**，B 再激活 | 横幅写明账路径；ECU 流水 `F2` / `F1`；退账"2 条租约，未归还 0"；账文件版本行 / 36 字符 / 16 位校验和；对账"可唯一还原 2 条"，给出 `0x0E01（位子 2）` 与 `0x0E00（位子 1）`；`--strict` 退出 0 |
| 二 撞位子 | A 干完断开，`0x0E02` 再来 | 两笔在 ECU 侧都是 `F1`；日志里两台都拿位子 1（复用证据）；对账"歧义 2 条"、候选 `0x0E00 / 0x0E02`；`--strict` 退出 **2** |
| 三 空账 | 网关**不开** `--stamp-sa`，但仍给 `--slot-ledger` | 退账明说"空账：本次没开 `--stamp-sa`"；账文件合法但 0 条租约；对空流水说"这条账上没有流水——没什么可对" |

段二不是"故意造个失败"，它验的是**这一步最该说清的事实**：位子会回收，这是设计事实。工具的正确行为是把不可判定的标成不可判定。

另有两条独立断言不给账：

- `doip-audit --key-store <b>`（无 `--slot-ledger`）→ "可唯一还原 0 / 歧义 0 / **查不到 2**"，并明说"没给账"；
- 段三的空账 → 账合法、里头没人，结论"没什么可对"，**不硬凑**。

## 11. 踩到的坑

1. **`ledger_` 撞名**。`DoIpTcpServer` 里 M12 已有 `StreamLedger ledger_`；再加一个同名字段，编译器报"重声明"，人看到的却是"这个成员明明有 `text()`"——名字解析到了另一个类。改名 `slotLedger_`。**同一个类里两本账，名字必须带着它们在记什么。**
2. **`LoadResult` 里装 `SlotLedger` 自己**。类内 `struct LoadResult { SlotLedger ledger; }` 是"不完整类型"，编译不过。改成输出参数 `parse(text, out, why)` / `load(path, out, why)`。**返回一个包含自己的结构，在 C++ 里是最直白的不可能。**
3. **测试里"此刻没人占着"想当然了**。B7 断言 `openCount == 0`，但同一个测试块的 2 号槽还开着。错的是断言的**主语**，不是实现。改成"只有 2 号还占着"。**一句断言里出现"都/全/没有"，先问一句"那另一个呢"。**
4. **段三的期望值抄了段二**。段三没起诊断仪，ECU 盘是空的，工具走的是"这条账上没有流水"那条早返回，脚本却按"查不到 2 条"断。**验收脚本每一段都要能被单问一句"它到底动了什么"。**
5. **`substr($0, 31, 8)` 差 2**。awk 从 1 开始数，设计里写的是 0-based 偏移 28。定长格式的偏移一律**从算术推**（`2+1+2+1+4+1+8+1+8+1 = 29`），不靠数手指。
6. **老腿 m25 在 CI 上偶发"零应答"**。全量 CI 第 29 步，启动那条广播 `22 F1B2` 三台一条都没回，紧跟着三条断言全空；单独重跑 m25 是 24/24。根因是功能应答按固定窗口逐通道轮询（M8 的边界），机器忙时 ECU 起得慢就错过窗口。修法：`m25_check.py` 的 `broadcast()` 只在"一条都没回"时重试（最多 3 次、间隔 0.4s），回了哪怕一条就不重试。**重试吃掉的是启动抖动，不是把红变绿。**

## 12. 与 M26 / M28 的关系

- **M28 的 `actor` 是这条链的上游**：没有 `L` 行末尾那 2 个字符，这里就没有"位子"可还原。M29 一个字节都没动 ECU 侧格式（仍是 v4、38 字符）。
- **M26 的流水是同一套落盘思路的第三次复用**：版本行 + 定长行 + `SUM`。第三次用同一套骨架，说明这套骨架选对了；但也说明**它不防篡改**这个缺口被复用了三次。

## 13. 边界

- 位子仍只有 8 个；**任何一次复用都会让那次运行里所有对应流水永久歧义**。
- 账**不签名**：`SUM` 只防手滑与半截文件，改完重算照样过。
- **不按时间插值**：两边没有共同时基，"按秒推算是哪台"这件事故意不做。
- 两边各记一半能暴露**笔误**，不能暴露**篡改**：两份账都在同一个人手里。
- 对账依赖这一次真的落了账：没开 / 截断 / 删掉，工具只会说"查不到"。
- `P` 行的连接号与秒都是**进程内**量，跨进程不能比。
- 网关自己的请求日志没有导出格式，对账只对 ECU 侧。
