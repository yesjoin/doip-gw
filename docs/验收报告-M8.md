# M8 验收报告：功能寻址（一条广播 → 多台 ECU 应答）

验收目标不是"能往 7DF 发一帧"，而是**证明答案的条数与归属都是对的**：
一条广播出去，几台 ECU 答、分别是谁答的、答了什么，三者都要对得上。

- 复现：`bash tools/m8_e2e.sh 13462`（自起两台 ECU + 网关 + 总线录制，约 40 秒）
- 结果：**通过 15 项，失败 0 项**；单元断言 464 条（6 套件，`doip-route` 由 57 → **100**）；
  `ci_local.sh` **12 步 25 项**全绿

## 拓扑（同一条 vcan0）

| 角色 | 逻辑地址 | CAN 收发 | 听广播 | VIN / HW |
|---|---|---|---|---|
| 网关实体 | `0x0001` | — | — | UDP 发现声明 VIN `LSVAA0000A1234567` |
| ECU_B（`stub-ecu`） | `TA=0x0003` | `7A0`/`7A8`（11 位） | `7DF` | VIN `LSVZZ0000B7654321`，HW `HW02` |
| ECU_C（`stub-ecu`） | `TA=0x0006` | `18DA00F1`/`18DAF100`（29 位） | `7DF` | VIN `LSVCC0000C7654321`，HW `HW03` |
| 功能地址 | `TA=0xE400` | 广播 `0x7DF` | — | 厂商自定义功能组 |

## 八步十五项

| # | 要证明的事 | 实测 |
|---|---|---|
| 1 | 物理表 + 功能表分开打印 | `TA=0xE400 → 0x7DF（所有 ECU 都在听）`，物理两条仍在 |
| 2 | 一次广播回来 **2 条**，SA 不同 | `SA=0x0003 → 62 F1 91 48 57 30 32`、`SA=0x0006 → 62 F1 91 48 57 30 33` |
| 3 | 换服务同样成立 | `3E 00` → 两条 `7E 00` |
| 4 | 响应塞不进单帧时不许装能答 | `22 F1 90`（VIN 20 字节）→ **0 条** + `0x8003 0x06` |
| 5 | 请求超过 7 字节当场拒 | 8 字节 → `0x8003 0x04`（报文太大） |
| 6 | 广播之后物理寻址照常 | `TA=0x0003` / `TA=0x0006` 各读到自己的 VIN |
| 7 | 总线侧：广播只发一次 | `candump` 里 `7DF` 恰好 **3** 帧（3 次广播），`7A8` 与 `18DAF100` 都有 |
| 8 | 网关的账 | 广播 3 次、收回应答 4 条、无人应答 1 次；两条通道各记 2 条广播应答 |

## 总线样本（`candump -L` 原始行）

```
(1795517370.419728) vcan0 7DF#0322F19100000000      ← 广播（1 条，所有 ECU 都在听）
(1795517370.419779) vcan0 7A8#0762F19148573032      ← ECU_B 的应答（11 位）
(1795517370.419838) vcan0 18DAF100#0762F19148573033 ← ECU_C 的应答（29 位）
(1795517371.505045) vcan0 7DF#023E000000000000
(1795517371.505100) vcan0 7A8#027E000000000000
(1795517371.505188) vcan0 18DAF100#027E000000000000
```

一次广播、两条不同宽度的应答，SA 在 DoIP 侧分别是 0x0003 / 0x0006 —— 这就是"谁答的要说清"。

## 网关记账（同一次跑）

```
功能寻址：广播 3 次，收回应答 4 条，无人应答 1 次
  TA=0x0003（0x7A0/0x7A8）：转发 3 条，失败 1 条，发帧 5，收帧 5，超时 0，序号错 0，迟到帧丢弃 0，广播应答 2
  TA=0x0006（0x18DA00F1/0x18DAF100）：转发 3 条，失败 1 条，发帧 2，收帧 5，超时 0，序号错 0，迟到帧丢弃 0，广播应答 2
```

3 次广播：`22 F1 91`、`3E 00` 各回 2 条（共 4 条），`22 F1 90`（VIN）两台都不答 → 记 1 次"无人应答"。
**"无人应答"单独计数**：它和"传输出错"错因不同（前者查"支不支持这个服务"，后者查线）。

## 关键设计：单帧是协议限制

- 请求必须单帧（≤7 字节）：广播没有唯一收件人，**流控帧无处可发**。超过就被 `0x8003 0x04` 拒。
- 响应也必须单帧：ECU 发首帧后同样等不到唯一流控方向，所以读 VIN 在功能寻址上"没有答案"。

## 真踩到的坑（M8 最大的一处）

首次跑 `m8_e2e.sh`：15 项红了 12 项，网关日志满屏 **"没有装下游，只回 ACK"**，
可 `diagnosticSinkMulti` 明明装了。

根因：M3 的老守卫 `if (!diagnosticSink) { log(...); continue; }` 排在新的多响应分支**前面**，
M8 只装多响应 sink，于是请求在旧守卫处就被 `continue` 掉，广播一次都没发生。
删掉旧守卫、把"没有下游"的兜底挪到最后，一次全绿。

教训：**加新分支前先看它前面有没有"提前返回"的老守卫**——守卫本身不错，错在它按旧假设工作（"下游只有一种"）。

## 单元断言新增 43 项（`route_selftest` D 段）

| 组 | 覆盖 |
|---|---|
| 地址段边界 | 0x0DFF / 0xE000 / 0xEFFF / 0xF000；0xE000–0xE3FF 为保留区、0xE400 起可用 |
| 正常入表 | 0xE400→0x7DF 进功能表、不进物理表、可按地址查回广播 ID |
| 拒绝 | 物理地址当功能地址、保留区地址、广播 ID 为 0、超 29 位、功能地址重复、广播 ID 重复 |
| 互踩 | 广播 ID 撞物理 ID、物理 ID 撞广播 ID、功能地址写进物理表 |
| reachable | 物理/功能都算能到；`known()` 与 `knownFunctional()` 各管一张表 |
| 宽度叠加 | 29 位广播 `0x18DB33F1` 能进表，日志打成 8 位 |

## 已知边界

- 端到端只跑 11 位广播 `7DF`；29 位广播 `0x18DB33F1` 只过了单测。
- 应答是**串行轮询**每条通道收的（每通道 150ms 固定窗口），ECU 慢于窗口按没答处理。
- 功能寻址只接受单帧响应，收到多帧会跳过并计 `funcMultiSkip`。
- 一个 `0x8001` 只对应一次 CAN 广播，不做多网卡/多路 CAN 分发；应答不去重、不按到达时间排序。
- `0x8003` 码用点：请求 >7 字节 → `0x04`；广播无人应答 → `0x06`；功能地址不在表 → `0x03`。
