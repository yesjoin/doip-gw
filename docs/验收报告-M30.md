# 验收报告 · M30：按操作分权限（读 < 写 < 刷写三档）

> 项目三 `doip-gw`（DoIP 诊断网关）· 第 31 个里程碑
> 一句话：**M27 认人，M30 认权。** 有票只说明"你是你自称的那台"，不说明"这台配做这个动作"。

---

## 1. 这一步要解决的问题

到 M29 为止，网关能回答的问题是：

- 这条 TCP 连接自称 SA `0x0E00`，它手里的票对不对（M27）；
- 这个 SA 在 CAN 侧用哪个位子说话（M28）；
- 这个位子在这次运行里到底是谁（M29）。

**但没有一处拦得住"有票的读档诊断仪拿 `0x31` 装钥匙、拿 `0x34` 刷写"。** 认证是"你是谁"，授权是"你能干什么"——两件事，缺一半。

M30 补的是后者：网关只看 UDS 的第一个字节（服务号），把它归到三档之一，越权就**不转发**。

## 3. 机制：一张表 + 一次判定

```cpp
enum class Tier { None, Read, Write, Flash };
OpInfo  { sid, need, what };                 // what 是给日志看的人话
classify(uds, len, out)      → 服务号 → 档（不认识 / ≥0x40 / 空载荷 → Flash）
class PermissionTable        → grant(sa, tier) / levelOf(sa) / decide(sa, need)
Decision { permit, need, have }              // 判定结果自带"要什么 / 有什么"，方便日志
```

档位表（阶梯，读 ⊆ 写 ⊆ 刷写）：

| 档 | 服务号 |
|---|---|
| 读 | `0x22` 读数据、`0x19` 读 DTC、`0x3E` 保活 |
| 写 | `0x10` 会话、`0x11` 复位、`0x14` 清 DTC、`0x27` 安全访问、`0x28` 通信控制、`0x2E` 写 DID、`0x2F` IO 控制、`0x83` 时序参数、`0x85` DTC 设置 |
| 刷写 | `0x31` 例程、`0x34` 请求下载、`0x36` 传块、`0x37` 退出传输 |

为什么 `0x27` 在写档而不是刷写档：它是"为写开门的动作"，真正动代码的是 `0x31/34/36/37`，那四条已经在刷写档。为什么 `0x31` 整条按刷写：`FF 00` 只查、`FF 01` 才擦，只看服务号分不开，宁可严。

为什么"不认识的一律按刷写"：中间档最危险——它看起来不危险。安全默认只有两个方向，要么全挡、要么全放，选全挡。

## 4. 权限绑 SA，不绑连接号、不绑位子

- 连接号每次重连都变（TCP 的端口是随机的）；
- 位子会回收（M29 段二就是"1 号位子先后两台"）。

**权限绑的是人**（SA），所以 `--grant 0E00:read` 这种写法在主客体上是稳定的。

## 5. 越权时：不转发 + 替 ECU 回 `7F <SID> 33`

- **不转发**：请求根本不上总线。否则 ECU 会真的执行——防火墙就成了"事后通知"。
- **回 `0x33`**：UDS 里现成的 `securityAccessDenied`。诊断仪那边的处理路径是标准的（换钥匙、提示无权限），不需要额外约定。
- **不用 DoIP 的 `0x8003`**：`0x8003` 的码表是 `0x02` 源地址非法 / `0x03` 目标未知 / `0x04` 太大 / `0x05` 内存不足 / `0x06` 不可达 / `0x07` 网络未知 / `0x08` 传输层错误——没有"没权限"这一格。硬塞等于自造协议。
- **先 ACK 再拒**：`0x8002` 说的是"报文收到了、格式对"；权限是应用层的话。先 ACK 后拒，诊断仪才分得清"没收到"（该重发）和"收到但不让做"（重发无用）。

## 6. 默认关，横幅点名，退账按档计数

横幅（开时）：

```text
诊断防火墙：开（按 SA 分三档：读 < 写 < 刷写；不认识的服务号按刷写档要求）
  SA 0x0E00 → 读
  SA 0x0E01 → 写
  SA 0x0E02 → 刷写
  默认档：读（没列出来的 SA 按这一档）；越权时不转发，网关替 ECU 回 7F <SID> 33
```

关时也要说得出口：`诊断防火墙：关（网关只做传输，不看服务号；加 --enforce-ops 才打开）`。

每条挡回都点名：

```text
权限挡回：SA 0x0E00 想「写 DID(0x2E)」(写档)，但它只有「读」→ 替 ECU 回 7F 0x2E 33（未转发）
```

退账按档分类：`权限：放行 14 条，挡回 6 条（要读 0 / 要写 3 / 要刷写 3）`——"想读被挡"正常应该是 0（读是最低档），这条数字本身就是自检。

## 7. 50 项端到端怎么验收的

| 段 | 起什么 | 验什么 | 项 |
|---|---|---|---|
| 一 | 防火墙开；`0x0E00` 读 / `0x0E01` 写 / `0x0E02` 刷写；ECU `0x0006` 带 `--flash --secure` | 读档：`22 F190` → `62 F190…`、`22 F186` → `62 F186…`；`2E`/`10`/`27`/`34`/`0x39` 全 `7F xx 33`。写档：`10 02` → `50 02…`、解锁 → `6E F184`、`34` 仍 33。刷写档：`34` 穿到 ECU → `7F 34 22` | 32 |
| 二 | 同机同请求，网关不开 `--enforce-ops` | `2E` → `7F 2E 7F`、`34` → `7F 34 7F`；日志零"权限挡回" | 8 |
| 三 | 开防火墙、零授权、`--default-grant read` | 能激活、能读 VIN、写不了 DID | 5 |
| 横幅与退账 | 段一那只网关跑满 `--seconds` | 横幅五项 / 挡回日志点名 / 三档计数相加等于挡回总数 | 5 |

**段二是整份报告最要紧的一条**：33 和 22 的区别就是"网关挡的"和"ECU 挡的"。刷写档那条腿能拿到 `22`（没擦除）而不是 `33`，说明请求真的出去了；对照腿拿不到任何 33，说明这层不存在时世界长什么样。两段合在一起，才叫"验了这层"。

## 10. 踩到的坑

1. **测试把 `0x99` 当"不认识的"**：`0x99 ≥ 0x40`，实现走"响应码当请求"那一支，断言红。挑测试值时先确认这个值不会落进别的规则。换成 `0x39`。
2. **`--route 0x0003:7A0:7A8:仪表:` 尾部多一个冒号**：解析成 5 段，第 5 段只认 `fd` → 网关退出码 2。三条腿全起不来，报的却是"连不上"。**先看进程退没退。**
3. **后台进程 stdout 是块缓冲**：被 `pkill` 收掉时横幅、退账还在缓冲区里。两手修：`stdbuf -oL -eL`；退账断言改成 `wait $GW1` 等它自己跑完 `--seconds`。
4. **`"$STD"` 把带空格的命令前缀当成一个命令名**：`command not found`，脚本继续跑，看起来像"网关卡住"。
5. **ECU 没带 `--flash --secure` 时 `10 02` 回 `7F 10 31`**：这个 31 是 ECU 的"条件不对"，不是防火墙的。要验"网关放行、ECU 自己裁"，ECU 必须先具备条件。
6. **`50 02` 后面还有 P2/P2\*（`0032 01F4`）**：`== 50 02` 会红，期望值该取前缀。

## 11. 与 M27 / M29 的关系

- **M27 认证**：票对不对 → 拦"冒名"；
- **M30 授权**：档够不够 → 拦"有票但越界"；
- **M29 身份**：位子是谁 → 出事时能追到人。

三层各管一件事，且都**默认关**（M27 加 `--tester-key` 才开票，M30 加 `--enforce-ops` 才开防火墙），因为都在"网关本分"之外。

## 12. 边界

- **只挡网关这一跳**：能直接接 CAN 总线的人绕过它。这是拓扑，不是补丁。
- **档位是命令行配置，不是凭证的一部分**：改配置就能提权。M27 的票也是预共享密钥——同一个信任模型。
- **只看服务号，不看参数**：读档能不能读安全相关 DID（`F190`/`F1B0`）属于下一层（DID 白名单）。
- **`0x31` 一刀切**：`FF 00` 只查也会被挡。要细到子功能，分类键得从"服务号"扩到"服务号 + 子功能"。
- **没有速率限制**：被挡 1000 次和 1 次一样。挡回是日志，不是防线。

## 13. 结论

M30 交付的是一个**可开关、可点名、可退账**的网关侧授权层：读 < 写 < 刷写三档，越权不转发、替 ECU 回标准 `0x33`；端到端用三段（分档 / 对照 / 默认档）证明它真的把三档分开了，且关掉时回到"只做传输"的老行为。55 项单元 + 50 项端到端 + 34 步本地 CI 全绿。
